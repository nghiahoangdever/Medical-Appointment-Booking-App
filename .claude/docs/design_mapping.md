## State diagram → code

Each arrow is one row of `TRANSITIONS` (`appointmentStateMachine.ts`); each `[guard]` is a case in `guardFailure` (`appointmentRules.ts`). Full table: `appointment_state_machine.md`. `appointmentStateMachine.test.ts` fails if the table drifts from the diagram; `appointmentRules.test.ts` covers guard boundaries.

Guards to show on the diagram:

- `cancel [patient: own ∧ before shift start]`
- `checkIn [date = today ∧ before shift end]`
- `markNoShow [after shift start ∧ (doctor: own queue)]` (both arrows: from BOOKED and from CHECKED_IN)
- `start [own queue ∧ date = today ∧ doctor has no other patient in examination today (any shift)]`
- `complete [own queue]`

## Sequence diagrams → code

### "Patient books an appointment" (implemented)

Use these lifeline/message names — they match the code:

| Step    | Message                            | Code                                                                                                                            |
| ------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1       | load specialties                   | `GET /api/specialties` → `SpecialtyController.list` → `SpecialtyService.list` → `SpecialtyRepository.findAllActive`             |
| 2       | load doctors                       | `GET /api/specialties/:id/doctors` → `SpecialtyService.listDoctors` → `DoctorRepository.findActiveBySpecialty`                  |
| 3       | load availability                  | `GET /api/availability?specialtyId[&doctorId]` → `AvailabilityService.getAvailability` → `RosterRepository.findSlots`           |
| 4–5     | submit booking                     | `POST /api/appointments` → `authenticate` → `requireRole(PATIENT)` → `AppointmentController.book` (zod) → `BookingService.book` |
| 6.1     | window / shift-start check         | `bookingWindow`, `ShiftRepository.findById`, `hasTimePassed`                                                                    |
| 6.2     | duplicate check                    | `AppointmentRepository.findActiveForPatientInSlot`                                                                              |
| 6.3–6.5 | candidates, capacity, least booked | `RosterRepository.findSlots` → `pickLeastBooked`                                                                                |
| 6.6     | queue number                       | `RosterRepository.takeNextQueueNumber`                                                                                          |
| 6.7     | code                               | `generateAppointmentCode` + `AppointmentRepository.codeExists`                                                                  |
| 6.8     | create                             | `AppointmentRepository.create` (`bookedAt` = clock now)                                                                         |
| 7       | 201 response                       | `toAppointmentView` (with `allowedActions`) → `{ appointment }`                                                                 |
| 8       | confirmation                       | `BookingSuccess.tsx`                                                                                                            |

Steps 6.2–6.8 run inside `runInTransaction`. The step numbers are also in comments in `booking.service.ts`.

### "Receptionist checks in a patient" (implemented; optional extra diagram)

| Step | Message                                                        | Code                                                                                                                                                                                                                  |
| ---- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | load day list                                                  | `GET /api/appointments?date=…` → `AppointmentController.listForStaff` → `AppointmentService.listForStaff` → `AppointmentRepository.findForStaff` + `countByStatus` → `toStaffAppointmentView` (with `allowedActions`) |
| 2    | click "Check-in" (shown only if `CHECK_IN` ∈ `allowedActions`) | `ReceptionActions` → `appointmentsApi.checkIn(id)`                                                                                                                                                                    |

| 4    | load                                                           | `AppointmentService.perform` → `findVisibleTo` → `AppointmentRepository.findById`                                                                                                                                     |
| 5    | validate arrow                                                 | `transition(BOOKED, CHECK_IN, RECEPTIONIST)` (409 / 403)                                                                                                                                                              |
| 6    | validate guard                                                 | `guardFailure(facts, CHECK_IN, actor, now)` → `CHECK_IN_NOT_TODAY` / `CHECK_IN_SHIFT_ENDED` (409)                                                                                                                     |
| 7    | update                                                         | `AppointmentRepository.updateStatus(id, BOOKED, { status: CHECKED_IN, checkedInAt: now })` (0 rows → 409 `APPOINTMENT_CHANGED`)                                                                                       |

### "Doctor calls the next patient" (implemented)

Use these lifeline/message names; they match the code:

| Step | Message                                                                      | Code                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | load queue                                                                   | `GET /api/roster-entries/:id/queue` → `authenticate` → `requireRole(DOCTOR)` → `QueueController.queueForEntry` → `QueueService.getQueue` → `RosterRepository.findDutyEntry` (owner check, else 404 `ROSTER_ENTRY_NOT_FOUND`) + `AppointmentRepository.findByRosterEntry` + `findDoctorInExamination` → `toStaffAppointmentView` (with `allowedActions`) → `{ entry, appointments, nextAppointmentId, inExaminationElsewhere }` |
| 2    | click "Gọi bệnh nhân tiếp theo" (enabled only if `nextAppointmentId` ≠ null) | `DoctorQueuePage` → `doctorApi.callNext(entryId)`                                                                                                                                                                                                                                                                                                                                                                              |
| 3    | request                                                                      | `POST /api/roster-entries/:id/call-next` → `authenticate` → `requireRole(DOCTOR)` → `QueueController.callNext` → `QueueService.callNext`                                                                                                                                                                                                                                                                                       |
| 4    | check own entry                                                              | `QueueService.ownEntry` → `RosterRepository.findDutyEntry` (404)                                                                                                                                                                                                                                                                                                                                                               |
| 5    | find next                                                                    | `AppointmentRepository.findFirstCheckedIn(entryId)` (lowest `queueNumber`; none → 409 `NO_PATIENT_WAITING`)                                                                                                                                                                                                                                                                                                                    |
| 6    | start it                                                                     | `AppointmentService.start(doctor, id)` → `perform` inside `runInTransaction`:                                                                                                                                                                                                                                                                                                                                                  |
| 6.1  | load                                                                         | `findVisibleTo` → `AppointmentRepository.findById(id, tx)` (incl. `doctorInExamination`: the doctor's open exams that day, all shifts)                                                                                                                                                                                                                                                                                         |
| 6.2  | validate arrow                                                               | `transition(CHECKED_IN, START, DOCTOR)` (409 / 403)                                                                                                                                                                                                                                                                                                                                                                            |
| 6.3  | validate guards                                                              | `guardFailure(facts, START, doctor, now)` → `NOT_YOUR_PATIENT` / `EXAM_NOT_TODAY` / `DOCTOR_BUSY` (409)                                                                                                                                                                                                                                                                                                                        |
| 6.4  | update                                                                       | `AppointmentRepository.updateStatus(id, CHECKED_IN, { status: IN_EXAMINATION, startedAt: now }, tx)`                                                                                                                                                                                                                                                                                                                           |
| 7    | 200 response                                                                 | `toViewFor` → `{ appointment }`; client shows "Đang khám: …" and refreshes the queue                                                                                                                                                                                                                                                                                                                                           |

The plan's original `GET /api/doctor/queue?date&shiftId` became `GET /api/roster-entries/:id/queue` (see the change log).
